Build times doubled after 0.9 upgrade

Started by quietloop on 2025-03-11 · 18,402 views · 27 replies

quietloop Regular

After upgrading to 0.9 our CI went from 6 minutes to 13 minutes per build. Same runner image, same lockfile except for the upgrade itself. Anyone else seeing this?

I already tried --no-cache and a clean checkout. The slowdown survives both, which makes me think it is not the cache format change.

Reply 12
marcel Maintainer

We changed the default for parallelism from auto to 2 in 0.9 because the auto heuristic was oversubscribing small runners. On a 4-core box that halves the concurrency.

Set it back explicitly if your runner is not memory constrained:

[build]
parallelism = "auto"
