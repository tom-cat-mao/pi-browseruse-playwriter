Retention policy reference

A retention policy prevents objects from being deleted or overwritten for a fixed period. Policies are set per bucket and apply to every object written afterwards.

Retention tiers

The table below lists the supported tiers. The minimum lock period is enforced by the service; shorter values are rejected with 400 InvalidRetentionPeriod.

Tier Minimum lock Maximum lock Object size limit Early delete fee
standard 1 day 3 years 5 TiB none
compliance 90 days 10 years 5 TiB prorated storage
archive 180 days 7 years 500 GiB retrieval cost

Enabling a policy

Set the tier with the CLI and confirm the resulting lock period:

storage bucket retention set --bucket media --tier compliance
storage bucket retention describe --bucket media

Policies take effect for new writes only. Objects written before the change keep their previous retention state until it expires, which is why the migration notes recommend a two-week window.

Limits

  • One policy per bucket; changing tiers does not shorten existing locks.
  • Up to 100 lifecycle rules per bucket, each referencing a retention tier.
  • Legal holds override retention and can only be released by an account owner.
