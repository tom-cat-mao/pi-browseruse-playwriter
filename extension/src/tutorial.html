让 Pi 操作你本机 Chrome 里的真实标签

Pi Browser Use 让 Pi agent 通过本机 Chrome 扩展，读取和操作你已经打开的标签页，包括你已登录的账号。 浏览器始终留在你的电脑上，没有云端浏览器。

本页是静态说明，不会自动连接、不会接管或打开任何标签，也不会显示实时连接状态。下面所有需要你手动执行的东西， 都要你自己在终端或 Pi 里输入。

快速开始

这套东西由四部分组成，缺一不可。先建立这个整体概念，可以省掉后面一大半排查时间。

本机 Chrome

就是你现在正在用的浏览器。扩展不会启动一个新的 Chrome，也不要求你用特殊参数重启浏览器。 你平时登录的账号、Cookie、表单内容都在这个浏览器里。

Chrome 扩展

通过 Chrome 调试协议把某个标签交给 agent。新标签只有在你明确要求、或你自己点击工具栏图标时才会被接管； 重新连接时它只会恢复仍然受控的标签，已经释放的标签不会自己回来。

配对 runtime

一个跑在你本机的本地服务（@tom-cat/pi-browser-runtime），默认监听 127.0.0.1:19989，数据目录 ~/.pi-browser-use。 Pi 里的 browser_* 工具通过它和浏览器通信。

Pi 包

@tom-cat/pi-browser-use-extension，提供 browser_* 工具和 /browser-status 命令。它只负责执行和汇报事实，具体怎么操作由模型决定。

登录态意味着隐私。 agent 看到的是你真实的页面，可能包含你的个人信息、邮件、后台数据。 只接管你愿意让它读取的标签，任务结束后及时释放。

三步跑通

  1. 1 在源码检出里安装 Pi 包并构建 runtime（这一步必需，见 安装 Pi 包并构建 runtime）。
  2. 2 加载 Chrome 扩展（GitHub Release 的 ZIP 需要手动加载，见 加载 Chrome 扩展）。
  3. 3 在 Pi 里选 Chrome profile，再 discover / attach 你指定的标签（见 第一次使用）。

现在的发布状态

  • 没有 npm 发布：Pi 包和 runtime 目前要从源码本地安装。
  • 没有上架 Chrome 应用商店：扩展只能以「加载已解压的扩展程序」的方式手动加载。
  • 官方下载入口是 GitHub Releases 里带版本号的 pi-browser-use-extension-<版本>.zip，不要用 GitHub 自动生成的源码压缩包。 打开 Releases 页面

怎么再次打开本页

本页是扩展的选项页：到 chrome://extensions 找到 Pi Browser Use，在详情里点 「扩展程序选项」；或在工具栏图标上点右键，选择「选项」。

安装

Pi 包、本机 runtime 和 Chrome 扩展是三个独立部分，都要各自装好：扩展的 ZIP 里没有另外两个， pi install 也不会替你装浏览器扩展。

1. 安装 Pi 包并构建 runtime（必需）

前提是这台机器已经装好 Pi（@earendil-works/pi-coding-agent），终端里的 pi 命令可用。当前没有任何 npm 发布，所以 Pi 包和 runtime 只能从源码检出安装， 在检出目录里按顺序执行下面几条：

终端 
git clone --branch dev https://github.com/tom-cat-mao/pi-browseruse-playwriter.git
cd pi-browseruse-playwriter
pnpm bootstrap
pnpm --filter @tom-cat/pi-browser-runtime build
pi install ./pi

这几条不是可选项，跳过就不会有可用的工具：pnpm bootstrap 初始化 playwright 子模块并构建本地 playwright-core；pnpm --filter @tom-cat/pi-browser-runtime build 产出 runtime 本体 （playwriter/bin-runtime.js 加载的 dist/ 由它生成）与两个后端的扩展包。 pi install ./pi 装的是 Pi 侧的 browser_* 工具与 /browser-status， 它依赖同一检出里的 @tom-cat/pi-browser-runtime，所以必须排在构建之后。

装好后第一次在 Pi 里使用 browser_* 工具时，Pi 会自动启动配对的 runtime （也可以手动跑 node playwriter/bin-runtime.js）。默认配置：

  • 监听地址 127.0.0.1:19989（仅本机回环地址）。
  • 数据目录 ~/.pi-browser-use，日志默认写在 relay-server.log 与 cdp.jsonl。
  • 需要改地址或端口时用环境变量：PI_BROWSER_HOST、PI_BROWSER_PORT、 PI_BROWSER_TOKEN、PI_BROWSER_DATA_DIR。
  • 如果 PI_BROWSER_HOST 指向非回环地址，Pi 工具包会把它当成远端 runtime，不会在本机自动拉起进程。

2. 加载 Chrome 扩展

  1. 1 在 GitHub Releases 下载 pi-browser-use-extension-<版本>.zip。
  2. 2 解压到一个你会长期保留的固定目录，例如 ~/Applications/pi-browser-use-extension。
  3. 3 打开 chrome://extensions，打开右上角的开发者模式，点 加载已解压的扩展程序，选择包含 manifest.json 的那个目录。
  4. 4 加载完成后确认扩展 ID 是 eeklahpecooapnailfaebkjjembkjhhg（开发构建的固定身份）。

这个 ZIP 不是一键安装包。 桌面版 Chrome 上它必须配合「加载已解压的扩展程序」使用，Chrome 也不会自动更新它。 安装后不要删除或移动那个目录，否则扩展会立刻失效。真正的一键安装与自动更新要等应用商店上架。

3. 可选：自己构建扩展

上面两步是必需的；只有「不用 Release 里的 ZIP、自己构建扩展」这一件事是可选的。 需要 Node.js 20 以上、pnpm 10.18.1 和 Bun，并且已经完成第 1 步的检出与构建。

  • 开发态扩展构建：pnpm --filter mcp-extension build，输出在 extension/dist，再用上面的「加载已解压的扩展程序」指向它。
  • 本地打包：pnpm package:extension，产物（ZIP 与 .sha256）在 dist-release/。这只是本地打包，不会发布任何东西。
  • 构建与打包都不会安装扩展，也不会打开浏览器。

第一次使用

典型请求是「看看我现在这个页面，接着往下做」。你不需要告诉 agent 网址，也不需要先建组： 让它先列出真实的标签，再原地接管你指定的那一个。

  1. 1 准备一个普通网页标签。 用 http/https 页面，不要用 chrome://、Chrome 应用商店或其它扩展的页面（见 无法接管某个标签）。
  2. 2 让 Pi 选 profile。 先用 browser_profiles 列出浏览器身份，确认 Chrome 是 connected； 还没连上就先看 profile 未连接。
  3. 3 discover 再 attach。 browser_tabs 的 discover 会列出真实打开的标签（标题、网址、窗口、是否当前标签， 只读元数据）；挑中之后用 attach 加 candidateId 原地接管。 接管不会刷新页面、不会搬窗口，滚动位置和表单内容都会保留。
  4. 4 观察 → 操作 → 再观察。 browser_snapshot 返回 aria-ref=eN 引用和 snapshotId； browser_click / browser_fill 用引用时必须同时带上 snapshotId。 每一步操作之后重新 snapshot 校验，不要连着盲操作。
  5. 5 页面变了就重新读。 任何 browser_evaluate 或 browser_execute 都会让最新 snapshot 失效—— 即使那次调用只是读数据。旧引用会报 stale-snapshot，必须重新 snapshot， 不能假设「刚才只是只读」而跳过验证。

工具栏图标怎么用

Chrome 版没有弹窗：点图标会直接对当前标签执行动作，不会弹出任何面板。要确认真实状态，请在 Pi 里运行 /browser-status，它会报告 runtime 是否可达以及有哪些已连接的 profile。

  • 在普通标签上点击 = 接管（attach）。 对还没被接管的 http/https 标签点图标，会把调试器接到这个标签上，之后 Pi 就能操作它。
  • 在已受控标签上点击 = 取消控制并释放。 已经由 Pi 接管的标签，点图标等于释放：放弃控制，页面保持打开， 滚动位置和登录态都不动。
  • 在已断开的受控标签上点击 = 恢复接管。 之前断开过的受控标签再点一次会重新接上，不需要重新 discover。
  • 受保护的页面（chrome://、Chrome 应用商店、其它扩展的页面）点图标不会接管； 正在连接中的标签重复点击会被忽略。

结束控制

任务做完之后，用哪种方式收尾会直接影响你下次的体验，两者差别很大。

释放（release）

browser_tabs 的 action: "release"：放弃本会话对这个标签的控制， 页面保持打开，你的滚动位置和登录态都不动。 释放会留下记录，之后重连也不会把这个标签重新拉回本会话。

关闭（close）

browser_tabs 的 action: "close"：真正关闭这个标签页。 只在确定不再需要该页面时使用。

  • 点工具栏图标也能释放：对已接管的标签来说，点击等于「取消控制」，不会关页面。
  • Pi 会话结束时，runtime 只会释放这个会话的 worker，不会删除你的组和标签， 也不会停止共享的 runtime。
  • runtime 本身不会自己重新打开任何标签。
  • 推荐：任务结束后，把不再需要的标签 release 掉。这样即使后续沟通出错， agent 也不会顺手操作一个你以为已经交出去的页面。

排查

runtime 没运行 / 提示不可达

  • 先在 Pi 里跑 /browser-status。它是只读检查，会告诉你 runtime 是否可达、协议版本、 以及有几个 profile、其中几个已连接——不会创建任何资源。
  • 默认地址是 127.0.0.1:19989。地址不对时检查 PI_BROWSER_HOST / PI_BROWSER_PORT。
  • 第一次工具调用会自动启动配对 runtime。如果端口上已经有别的进程在监听、但它不是本产品的托管 runtime，Pi 会直接报错并说明「refusing to replace it」，不会覆盖或替换它。 请先确认那个进程是什么，再决定是否换端口。
  • 手动启动路径是 node playwriter/bin-runtime.js（在源码检出目录里）。 也可以用 PI_BROWSER_RUNTIME_PATH 指定 runtime 入口。
  • runtime 需要认证时设置 PI_BROWSER_TOKEN；token 不对会直接被拒绝。

profile 未连接

  • 确认 Chrome 正在运行，并且扩展在 chrome://extensions 里是启用状态（不是被禁用或移除）。
  • 确认扩展目录还在原来的位置、没有被移动或删除。
  • 确认 runtime 可达：runtime 没起来时，扩展无法建立连接。
  • 如果同一身份装了两份构建，会出现 extension-replaced 状态——同一时间只允许一份接管。 把多余的移除或禁用，再点一次图标重连。
  • browser_profiles 里只有 connected 的 profile 才能用来建组建标签； 没有可用的 Chrome profile 时，先解决上面几条，再看 runtime 不可达。

无法接管某个标签

  • 受保护页面不能接管：chrome:// 开头的页面、devtools://、 edge://、Chrome 应用商店（chrome.google.com / chromewebstore.google.com）以及其它扩展的页面。换成普通 http/https 页面再试。
  • 已经被另一个 Pi 会话接管的标签会被拒绝；一次只接管你明确指定的那一个标签。
  • discover 的结果可能被分页：回复里会给出 total / returned / nextOffset / truncated。找不到你的标签时，按 nextOffset 继续往下读，而不是假定它不存在。
  • 新窗口打开的标签会关联到来源标签，用 browser_tabs 的 sourceTabId 去找，而不是靠网址或「最后一个标签」。

能力与行为上的限制

  • CSS / role 选择器是严格匹配：命中 0 个或多个都算错误，不会有自动的 .first() 回退。 要精确元素就用 snapshot 的引用。
  • browser_snapshot 的引用只在产生它的那次 snapshot 内有效，页面变化后必须重新 snapshot。
  • browser_evaluate 里的代码必须显式 return，只写表达式会返回 undefined。
  • 取消或超时不会重放。结果里 outcome 为 unknown 时，说明动作可能已经部分发生—— 先 snapshot 观察，不要重复点击。
  • browser_execute 在隔离沙箱里跑，每次调用相互独立，page / locator 句柄不能跨调用复用。
  • browser_execute 里不要调用 browser.close() / context.close()； 关标签用 browser_tabs。Chrome 上 mouse / touchscreen 也不可用。
  • 没有导出 PDF 的工具（它在有界面的扩展会话里一直失败，已被移除）。
  • 截图是可选的补充，读取页面内容用 browser_snapshot 更省也更准。

隐私

浏览器不会离开你的电脑：扩展通过本机调试协议与本机 runtime 通信，没有云端浏览器，数据目录也在本机。 但 agent 操作的是你真实的登录态页面，请只接管你愿意让它读取的标签。

Pi Browser Use 是 remorses/playwriter 的维护 fork，保留 MIT 许可与上游署名。本页是扩展内的本地页面，离线可用，不加载外部脚本、字体或 CDN。
